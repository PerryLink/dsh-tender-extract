# 条文核查报告 —— 招标类四个插件：《招标投标法》全文与条号回填

**适用插件**：`dsh-tender-extract`、`dsh-tender-matrix`、`dsh-bid-qual-check`、`dsh-bid-ca-precheck`

- **核查日期**：2026-10-07
- **核查方法**：取得官方转载全文，逐条比对规则 `basis` 的**主题**与条文的**内容**。
- **结论**：**《中华人民共和国招标投标法》全文取得**（六章六十八条）。
  本报告**做两件事**：① 把此前 28 条「本次未取得条号」的引用**按主题回填为具体条号**；
  ② **不提高任何 `kind` 或 `severity`**（理由见第四节）。

| 规则主题 | 回填条号 | 条文要点 |
|---|---|---|
| 招标文件应当包括的内容 | **第十九条** | 「招标文件应当包括招标项目的技术要求、对投标人资格审查的标准、投标报价要求和评标标准等**所有实质性要求和条件**以及拟签订合同的主要条款。」 |
| 招标文件不得含有的内容 | **第二十条** | 「招标文件不得要求或者标明特定的生产供应者以及含有倾向或者排斥潜在投标人的其他内容。」 |
| 标段划分与工期 | **第十九条**（第三款） | 「招标项目需要划分标段、确定工期的，招标人应当**合理划分标段、确定工期**，并在招标文件中载明。」 |
| 澄清与修改的时限 | **第二十三条** | 「……应当在招标文件要求提交投标文件截止时间**至少十五日前**，以书面形式通知所有招标文件收受人。」 |
| 编制投标文件的合理时间 | **第二十四条** | 「……自招标文件开始发出之日起至投标人提交投标文件截止之日止，**最短不得少于二十日**。」 |
| 招标公告/邀请书应载明事项 | **第十六条**（第二款）、**第十七条**（第二款） | 公告与邀请书应载明「招标人的名称和地址、招标项目的性质、数量、实施地点和时间以及获取招标文件的办法等事项」。 |

### `dsh-tender-matrix`（评标办法矩阵）

| 规则主题 | 回填条号 | 条文要点 |
|---|---|---|
| 评标委员会的组成 | **第三十七条** | 「评标委员会由招标人的代表和有关技术、经济等方面的专家组成，**成员人数为五人以上单数**，其中技术、经济等方面的专家**不得少于成员总数的三分之二**。」该条并规定「与投标人有利害关系的人**不得进入**相关项目的评标委员会」「评标委员会成员的名单在中标结果确定前应当保密」。 |
| 按招标文件确定的评标标准和方法评审 | **第四十条**（第一款） | 「评标委员会应当按照**招标文件确定的评标标准和方法**，对投标文件进行评审和比较；设有标底的，应当参考标底。」 |
| 中标人的条件 | **第四十一条** | 两项之一：「（一）能够**最大限度地满足**招标文件中规定的各项**综合评价标准**；（二）能够满足招标文件的实质性要求，并且经评审的**投标价格最低**；但是投标价格低于成本的除外。」 |
| 评标报告与中标候选人的推荐 | **第四十条**（第一款末句） | 「评标委员会完成评标后，应当向招标人提出**书面评标报告**，并**推荐合格的中标候选人**。」 |
| 否决所有投标 | **第四十二条** | 「评标委员会经评审，认为所有投标都不符合招标文件要求的，**可以否决所有投标**。」 |
| 评标期间禁止谈判 | **第四十三条** | 「在确定中标人前，招标人**不得与投标人就投标价格、投标方案等实质性内容进行谈判**。」 |

| 招标人的资格审查权 | **第十八条**（第一款） | 「招标人可以根据招标项目本身的要求，在招标公告或者投标邀请书中，要求潜在投标人提供**有关资质证明文件和业绩情况**，并对潜在投标人进行**资格审查**；国家对投标人的资格条件有规定的，依照其规定。」 |

## 三、⚠️ 本轮**没有**改动的东西（必须写明）

1. **`kind` 一律未提高**。上述 28 条**原为 `derived-from-principle` 或 `institutional-configuration`**，
   **本轮只回填条号，未改为 `direct`**。理由见第四节。
2. **`severity` 一律未改动**。特别是 `dsh-bid-ca-precheck` ——
   该插件 README 明确记载「**没有任何规则可以是 `error`**」，
   **本轮不得因为取得了条文就把它变成 error**，否则与 README 的边界声明冲突。
3. **`excerpt` 一律未改动**（保持「该条文本次未取得」的如实标注）。
   ⚠️ 这里要说明一个容易误会的点：**`clause` 已回填为具体条号，而 `excerpt` 仍写"未取得"** ——
   这**不是自相矛盾**，而是反映真实状态：**本报告核对的是"该条号的主题与规则主题相符"，
   并未逐字核对每条规则的 `excerpt` 是否等于条文原句**。若把 `excerpt` 换成条号对应的句子，
   就等于声称"我已经把它条文原文抄下来了"—— 那需要把每一条的 `excerpt` 与该条号逐字对照后再做。

## 四、为什么不把 `kind` 升为 `direct`

1. **核对对象不同（一贯口径）**：本法规范的是**招标人与投标人的行为**；
   本插件核对的是**招标文件／投标文件的抽取与比对结果**。
2. **本条主题相符 ≠ 该规则的要求是条文明文**。例如 `TE-002`（招标文件不得含倾向性内容）
   与**第二十条**主题相符，但本插件的检查是"抽取结果里是否出现了指向性表述"，
   而条文规范的是"招标文件**不得要求或标明**特定生产供应者"——**表述对象不同**。
3. **本法 1999 年公布，2017 年修正情况本次未核实**，在版本不确定时提高定级不诚实。
4. **`dsh-bid-ca-precheck` 的 README 已向用户承诺"无 error 规则"**，升 `kind` 会动摇该承诺。
